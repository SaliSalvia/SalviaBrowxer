# قرارداد حفظ قدرت موتور رسانه — SalviaBrowxer

**این سند یک شرط مهندسی است، نه متن تبلیغاتی.** هدف محصول، تجربه‌ای نزدیک به Video Downloader از InShot Inc. با مرورگر داخلی و موتور تشخیص/دانلود عمومی‌تر است؛ اما «قوی‌تر بودن» فقط پس از آزمون تکرارپذیر روی URLهای یکسان قابل ادعاست.

## ۱) محدودهٔ حفاظت‌شده

تا وقتی آزمون رگرسیون متناظر وجود ندارد، تغییر UI، Navigation، Compose، تنظیمات یا معماری نباید رفتار این لایه‌ها را تضعیف کند:

- `:core:model` — `MediaUrlRules`، `MediaSniffAdmission`، قواعد MIME/پسوند و سیاست Referer.
- `app/.../ui/utils/MediaSniffer.kt` و `MediaRequestObserver.kt` — تزریق زودهنگام، مشاهدهٔ پاسخ واقعی، dedupe و نسبت‌دادن نامزد به صفحه.
- `app/.../ui/bridge/MediaSnifferBridge.kt`، `MseRecordingBridge.kt` و مسیر `WebMessageListener` — پل کنترل‌شدهٔ صفحه به اپ و دادهٔ باینری.
- `:media:detector` — تشخیص مبتنی بر DOM و metadata، بدون حدس‌زدن APIهای خصوصی سایت‌ها.
- `:media:resolver` — probe و تحلیل HLS/DASH و کیفیت‌ها.
- `:media:downloader` — دانلود مستقیم، Range/parallel، فایل‌های staged، Resume، HLS/DASH، AES-128 غیر-DRM، retry محدود، ادغام صدا/تصویر و حمل نشست.
- `DownloadWorkQueue`، Room queue و `DownloadService` — تداوم صف، جلوگیری از اجرای تکراری و بازیابی پس از توقف سرویس/پردازش.

## ۲) ناوردایی‌هایی که نباید شکسته شوند

1. **یک منبع حقیقت:** قواعد رسانه فقط در `MediaUrlRules` نگهداری شوند و نسخهٔ تزریق‌شده به JavaScript از همان قواعد ساخته شود؛ کپی‌های مستقل و ناسازگار ممنوع.
2. **شاهد قبل از پیشنهاد:** نامزد از هدر پاسخ، media element واقعاً بارگذاری‌شده یا metadata معتبر صفحه می‌آید؛ `Accept` درخواست خروجی، اسم فایل حدسی یا URL یک API به‌تنهایی اثبات رسانه نیست.
3. **رد نویز:** Rangeهای جزئی، segmentها، فایل‌های سندی، Web App Manifest و پاسخ‌های غیررسانه‌ای نباید به‌عنوان دانلود کامل ویدیو عرضه شوند.
4. **حفظ انتساب:** نامزد دیررس از صفحه/پست قبلی نباید وارد سینی صفحهٔ جدید شود؛ انتخاب ویدیوی اصلی فقط از نامزدهای پذیرفته‌شده انجام شود.
5. **عدم ایجاد ترافیک پنهان:** مشاهدهٔ رسانه نباید بدنهٔ پاسخ صفحه را بخواند، درخواست اضافه بسازد یا صرفاً برای یافتن لینک، پخش را مختل کند.
6. **حمل نشست:** probe، playlist، segment، کلید AES-128 و Range باید UA و کوکی‌های مجاز همان نشست را حفظ کنند؛ Referer مطابق `SessionReferer` و سیاست امن cross-origin باشد.
7. **Resume واقعی:** توقف، مرگ process، خطای موقت و retry نباید فایل ناقص را به‌عنوان کامل منتشر کنند یا بخش‌های سالم را بی‌دلیل دوباره بگیرند.
8. **محدودیت منابع:** اتصال‌های موازی و retryها bounded باشند؛ فایل بزرگ یا playlist مخرب نباید حافظه/فضای ذخیره‌سازی نامحدود مصرف کند.
9. **خروجی قابل‌پخش:** video/audio جداگانه فقط در صورت موفقیت mux یک فایل ترکیبی معرفی شود؛ خطای remux باید اصل فایل را حفظ کند و فرمت خروجی را دروغین اعلام نکند.
10. **امتناع صادقانه:** DRM، stream زندهٔ نامتناهی و manifest غیرقابل‌پشتیبانی نباید به دانلود شکست‌خورده یا فایل غیرقابل‌پخش تبدیل شوند.

## ۳) مرزهای ثابت محصول

برای افزایش پوشش، به‌جای extractor اختصاصی برای هر سایت، از استانداردهای عمومی مرورگر و media pipeline استفاده می‌شود. این موارد خارج از محدوده‌اند:

- دورزدن DRM، paywall یا کنترل دسترسی؛
- استخراج/حدس توکن، امضای خصوصی یا API داخلی سایت؛
- جعل session یا تزریق هدر برای جعل هویت کاربر؛
- ضبط یا ذخیرهٔ پخش زندهٔ نامتناهی؛
- ادعای پشتیبانی از هر سایت یا ۱۰۰٪ موفقیت بدون آزمون واقعی.

سایت‌هایی که فقط از DRM یا API خصوصی استفاده می‌کنند ممکن است قابل دانلود نباشند. این یک محدودیت صادقانه است، نه مجوز تضعیف امنیت یا قانون.

## ۴) گیت اجباری قبل از ادغام تغییرات

### تست‌های هر تغییر مرتبط با مدیا

```bash
node --test scripts/test-media-sniffer.cjs
./gradlew :core:model:testDebugUnitTest
./gradlew :media:resolver:testDebugUnitTest
./gradlew :media:detector:testDebugUnitTest
./gradlew :media:downloader:testDebugUnitTest
./gradlew :app:testDebugUnitTest
```

CI باید این تست‌ها را در یک اجرای تمیز، سپس lint، `assembleDebug`، `assembleRelease` و `bundleRelease` اجرا کند. برای هر تغییر در مسیرهای Android/WebView/codec، تست instrumented نیز روی emulator اجرا شود.

### آزمون دستی دستگاه

تا پیش از اعلام «قوی‌تر از InShot»، هر دو اپ باید روی همان گوشی، Android/WebView version، شبکه، صفحه و URL آزموده شوند؛ حداقل ۳ اجرای مستقل برای هر سناریو. نتیجهٔ منفی نیز ثبت شود.

**سنجه‌های عددی:** نرخ تشخیص درست (recall)، دقت نامزدها (precision)، نرخ انتخاب اشتباه تبلیغ، زمان از آماده‌شدن player تا نمایش نامزد، زمان شروع دانلود، نرخ تکمیل، بایت‌های دوباره‌دریافت‌شده در Resume، پخش‌پذیری خروجی و صحت توضیح خطا.

نسخهٔ رقابتی فقط وقتی ادعا می‌شود که پوشش در سناریوهای بیشتر با precision قابل‌قبول و بدون افزایش false positive یا شکست دانلود به دست آمده باشد. افزایش تعداد ردیف‌های سینی به‌تنهایی «قدرت بیشتر» نیست.

## ۵) محدودهٔ تغییرات این سخت‌سازی

در این دور هیچ کد اجرایی در `media/detector`، `media/resolver`، `media/downloader`، `MediaSniffer`، پل MSE یا `MediaUrlRules` تغییر داده نشده است. تغییرات محدود به پایدارسازی CI، سقف‌گذاری ورودی verifier قفل پوشه و مستندسازی گیت‌های عدم‌رگرسیون هستند.
