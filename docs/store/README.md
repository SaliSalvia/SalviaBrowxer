# Play Store assets and listing copy

Everything here is instructions, not generated art. Do not generate trademark-infringing
screenshots (no YouTube, Instagram, TikTok or Netflix UI in any image).

## Listing copy rules

Allowed framing:

> SalviaBrowxer is a fast, private Android browser that saves videos and audio a page already
> offers you.

Forbidden framing — never ship any of these:

- "Download YouTube / Instagram / TikTok videos"
- "Download any video" or "works on every site"
- "Unlimited downloads", "bypass", "DRM bypass", "premium unlocked"
- claims about WorkManager, FFmpeg, yt-dlp, MPEG-DASH, AES-128 or live stream support

The app has no analytics, no ads and no account. Say that; it is true and it is the differentiator.

## Store listing — English

**App name (30 characters max):** `SalviaBrowxer`

**Short description (80 characters max):**

```
Private browser that saves the videos and audio a page already offers.
```

**Full description (4000 characters max):**

```
SalviaBrowxer is a fast, private Android browser whose defining feature is precision: when a page
already offers a video or an audio file, the app finds it and saves it, and when a page does not,
the app says so instead of guessing.

WHAT IT DOES

• A real browser. Tabs, private tabs, bookmarks, history, find in page, five search engines,
  JavaScript and cookie toggles, and a desktop-site switch that shows its state.
• A media tray that lists what the page actually exposed — direct files, HLS playlists with each
  quality, and DASH renditions when the manifest is one this app can honestly save. Media inside
  iframes and media that only appears in the page's scripts are found too.
• Downloads that behave: pause, resume, retry, parallel connections for large files, a real
  progress notification, and Wi-Fi-only mode for when you are on mobile data.
• A built-in player for what you saved, plus a lock for the downloads folder.
• English and Persian (RTL) throughout.

WHAT IT DOES NOT DO

• No "download any video" promises. No site-specific extractors: the app reports what the page
  offers, and refuses what it cannot save honestly — live streams, protected (DRM) streams, and
  blobs it cannot read.
• No account, no sign-in, no ads, no analytics, no crash reporting, no third-party SDK that
  phones home.
• No upload of your history, bookmarks, downloads or settings. Everything stays on the device.

PRIVACY, STATED PRECISELY

Pages load exactly as they would in any browser, so the sites you visit see your IP address and the
cookies they set, under their own policies. The developer never sees your traffic. Private tabs keep
no history and are never restored — and, honestly, they are not a separate identity: cookies and
site data are shared with your normal tabs, and the app says so in the tab switcher rather than
implying otherwise. The full policy is in the app and at the link below.

PRICING

Free, with no ads and no locked features. Source code is published under the GPL-3.0.
```

## Data safety form — the exact answers

Answer the Play Console form with these values; each one matches what the code does today.

| Section | Answer |
| --- | --- |
| Does your app collect or share any of the required user data types? | **No** |
| Is all of the user data collected by your app encrypted in transit? | Not applicable — no data is collected (the app's own downloads use the site's own HTTPS when the site offers it) |
| Do you provide a way for users to request that their data be deleted? | Not applicable — the app holds no data on any server. Local data is deleted by uninstalling the app or by clearing it in the app's own screens (history, bookmarks, downloads) |

If the form asks per-category (location, personal info, financial info, health, messages, photos and
videos, files and docs, calendar, contacts, app activity, web browsing, app info and performance,
device or other IDs), answer **not collected, not shared** for every row. Two answers deserve the
reason, because a reviewer will look for them:

- **Web browsing history.** The app visits the pages you ask it to visit, so those sites see your
  request as any browser's request — but the app itself transmits nothing to the developer, stores
  history only in a local database you can clear, and never writes private-tab visits to history.
- **Files and docs / photos and videos.** The app writes only the files you explicitly download. It
  reads no file it did not create, and it requests no storage permission.

Advertising ID: the app does not include the Play Services advertising SDKs and does not read the
advertising ID, so answer that the identifier is not used for advertising.

## Release checklist

1. **No version bump yet.** `versionCode = 2` / `versionName = "1.0.0"` stay as they are: the
   roadmap forbids advertising a capability (or a release) before the 10-site × 3-run device matrix
   passes on a real device, and that matrix is the owner's job — see
   [`docs/world-class-roadmap.md`](../world-class-roadmap.md). Bump only as part of shipping that
   verified build.
2. `./gradlew :app:bundleRelease` produces a signed `app-release.aab` (or upload the unsigned AAB and
   let Play signing apply). CI produces `app-debug.apk` and, when signing secrets exist, a signed
   `app-release.apk` — see `.github/workflows/apk_build.yml`.
3. `docs/privacy-policy.md` placeholders replaced and hosted at a public URL.
4. Data safety form: the table above, verbatim.
5. Store listing shows the privacy policy URL.
